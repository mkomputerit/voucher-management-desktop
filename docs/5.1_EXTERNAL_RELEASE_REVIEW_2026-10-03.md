## HIGH found and resolved — legacy placeholder versus live UniFi identity

### Failure mode

A pre-SQLite ZIP imported before the first live UniFi synchronization can create a synthetic historical voucher under a `legacy-backup://...` controller with a `legacy-backup-...` voucher identity.

Verified legacy HMAC print evidence may then be materialized correctly against that synthetic placeholder.

When the real UniFi voucher later appears, the previous implementation could retain two rows with the same voucher code:

1. the synthetic historical placeholder carrying the verified print fact;
2. the live voucher carrying the real UniFi UUID but no inherited print fact.

The generic legacy candidate set could also treat the placeholder and real UUID as competing identities, making an otherwise reconcilable event ambiguous.

This could produce contradictory operational facts: a historical row marked PRINTED while the real live voucher was treated as unprinted / awaiting alignment.

### Correction

The reconciliation path now converges a synthetic legacy placeholder to the real live UniFi identity only when all safety conditions are satisfied:

- the source identity is provably a `legacy-backup://` / `legacy-backup-...` placeholder;
- the target is a non-placeholder live identity;
- canonical voucher codes match;
- the placeholder has no controller sync observations;
- the placeholder has no non-migration operator/application activity;
- the placeholder was not privacy-archived/minimized.

When a preferred live controller is known, a matching synthetic placeholder is no longer treated as a competing candidate. Real-to-real collisions remain ambiguous and fail closed.

During a safe convergence the transaction:

- transfers verified legacy print rows to the live voucher;
- preserves existing live prints;
- rebuilds print sequence chronologically so first print / reprint semantics remain correct;
- transfers migration-only voucher events;
- repoints resolved `legacy_audit_events`;
- preserves the positive PRINTED fact;
- removes the provisional placeholder only after dependent facts have moved;
- records a `LEGACY_PLACEHOLDER_MERGED` migration audit event.

The operation fails closed instead of merging if the placeholder has acquired independent activity.

If the same legacy code maps to multiple live UUIDs, automatic convergence is blocked and requires technical review.

### Regression coverage added

The test suite now verifies:

- a live controller candidate shadows only the matching synthetic placeholder;
- a materialized legacy print converges to the true live UUID;
- an already-existing current live print is preserved;
- print chronology is rebuilt correctly: historical print remains sequence 1, later live print becomes reprint sequence 2;
- the synthetic placeholder is removed only after evidence is transferred;
- operator activity on the placeholder blocks automatic convergence;
- multiple real live UUIDs with the same code block automatic convergence.

- the automatic part is analysis only; mutation still requires operator confirmation and a verified encrypted pre-migration backup.
