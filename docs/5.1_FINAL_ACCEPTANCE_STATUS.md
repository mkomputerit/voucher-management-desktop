## Evidence rules

- **PASS — inherited** means a real operator test was already performed against
  the same reviewed application behavior and the final package change cannot
  affect that behavior.
- **PASS — automated exact candidate** means the frozen package itself passed the
  exact Windows CI/integration gate, but no claim is made about a manual field
  action.
- **PENDING — exact candidate field test** means the binding checklist requires
  a real Windows / real UniFi / real printer action that cannot be proven by CI.
- Earlier failed candidates are retained as regression evidence only; they are
  not treated as acceptance evidence.

## Minimum final field pass before merge

The remaining work should be performed on the frozen package candidate, not on
a newly rebuilt application-code commit.

Mandatory final checks:

1. install/launch the exact Setup or portable artifact on the deployment PC;
2. connect to the intended UniFi Site and run/read the privacy-safe contract
   smoke result;
3. verify Home authority after a real snapshot;
4. create temporary Nominale and Non nominale UAT vouchers;
5. perform one real PDF/physical print and one intentional reprint;
6. observe one real-use synchronization when practical;
7. exercise ordinary deletion only on a dedicated disposable UAT voucher;
8. perform the security-revocation destructive test only on a disposable fixture
   when this gate is required for the deployment;
9. open the final Voucher nominali and Voucher eliminati guide paths and verify
   preview;
10. create a password-protected backup with the frozen package and restore it on
    a disposable UAT data root.

No uncertain-create network interruption should be deliberately induced on the
production Site; that path is automated/lab-covered.
