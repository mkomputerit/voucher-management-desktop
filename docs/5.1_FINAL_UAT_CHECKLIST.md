# Voucher Management 5.1 — Final Field / Windows UAT Checklist

Status: release-gate checklist for the final 5.1 candidate.

This checklist starts only after the code-review gate is green. It verifies the
behaviors that GitHub CI cannot prove: the real UniFi controller contract,
Windows display/keyboard behavior, actual printer submission and the operator
workflow on the deployment PC.

## 1. Safety boundary

Do not use an existing operational voucher for destructive testing.

For write-path tests, create clearly identifiable temporary UAT vouchers and
delete/revoke only those temporary vouchers.

Before UAT:

- retain the current production backup;
- create one fresh verified .vmbk from the current test/archive state where
  applicable;
- record the exact candidate commit / GitHub Actions run;
- use the real deployment PC or a Windows PC with the same display scaling,
  printer path and user-account model;
- confirm the UniFi Site selected is the intended production Site.

The API key must not be copied into documents, screenshots, logs or command
history.

## 2. Gate A — read-only UniFi contract

Run the production adapter read-only smoke test against the intended controller:

tools/verify_unifi_contract_live.py

Pass criteria:

- connection succeeds with the official Integration API root;
- expected Site is selected;
- Network application version is reported;
- voucher pagination/list succeeds;
- when at least one voucher exists, direct GET by UUID succeeds and matches the
  list identity;
- no voucher code, name, UUID or raw Site UUID is printed by the tool;
- API key remains memory-only.

If the controller uses a local/self-signed certificate, validate the SHA-256
fingerprint through an independent trusted source before accepting/pinning it.

Any contract mismatch is a release stop. Do not adapt production data to make a
test pass.

## 3. Gate B — launch / installation behavior

Use the exact portable or Setup artifact from the selected candidate run.

### Setup

Verify:

- elevation is requested;
- application installs under Program Files;
- persistent data uses the intended ProgramData child;
- Start Menu entry works;
- existing ProgramData survives an application upgrade;
- ordinary uninstall removes program files but preserves ProgramData;
- explicit data removal is tested only on a disposable UAT data root.

### Single instance

With the application open, attempt a second launch.

Pass criteria:

- the second instance does not open a competing writer;
- the first instance remains healthy.

## 4. Gate C — display, DPI and keyboard

Repeat at least at:

- 100% scaling;
- 125% scaling;
- 150% scaling.

When two monitors are available, move the application between monitors with
different scaling.

Verify:

- no clipped primary buttons;
- no hidden fields in wizard/dialogs;
- voucher list remains readable;
- selected rows remain clearly visible in light and dark mode;
- Home KPI cards remain aligned;
- report guide remains usable;
- preview window remains usable;
- modal dialogs fit the usable screen area.

Keyboard checks:

- Tab / Shift+Tab move through actionable controls logically;
- Space/Enter activate the expected control where Windows convention applies;
- Escape/close actions do not leave hidden modal grabs;
- selection actions cannot accidentally make expired/archived vouchers
  printable/deletable.

A blocking layout or keyboard-navigation failure is a release stop.

## 5. Gate D — first connection / Home authority

Connect to the real UniFi controller.

Verify:

- controller/Site identity is the expected one;
- API key field is cleared after connection and is not present after restart;
- connection indicator is green only after an authoritative current snapshot;
- Home KPIs populate from the live controller, not stale SQLite history;
- a failed/partial refresh does not leave apparently authoritative green KPIs;
- recent vouchers show useful current entries;
- last backup timestamp is the last verified successful backup;
- the two threshold warnings are distinguishable.

Cross-check a small sample directly in UniFi.

## 6. Gate E — controller-discovered voucher alignment

Use a temporary voucher created outside Voucher Management, or an already known
safe external test voucher.

Verify:

- UniFi code/name/timestamps are read-only locally;
- voucher enters the alignment workflow;
- nominality is explicitly selected;
- without positive verified print evidence, completed alignment becomes
  NOT_PRINTED;
- the application does not invent a prior physical print;
- nominal classification is rejected if the UniFi name/recipient is empty;
- local notes are editable only one voucher at a time;
- nominality may be changed for multiple selected vouchers where allowed.

If verified legacy/SQLite print evidence exists for the voucher, verify that it
wins and cannot be downgraded.

## 7. Gate F — creation

Create dedicated temporary vouchers through Voucher Management:

1. one Nominale;
2. one Non nominale;
3. when operationally relevant, one multi-use voucher.

Verify:

- UniFi receives the expected controller-owned fields;
- created vouchers remain visible even if an immediate list refresh is delayed;
- local origin is Voucher Management;
- alignment is complete automatically;
- print state starts NOT_PRINTED;
- nominality matches the operator choice;
- Home refreshes from an authoritative snapshot.

Do not intentionally interrupt a production POST. Uncertain-create recovery is
covered by automated tests and should only be exercised in a disposable lab
environment.

## 8. Gate G — PDF and physical print

Select only UAT vouchers.

Generate the voucher PDF and verify visually:

- no "Destinatario:" prefix;
- recipient text stays inside the cut area;
- configured logo has the approved larger treatment;
- Unicode characters render correctly;
- labels/page geometry is correct.

Then submit one real physical print through the normal Windows print path.

Verify after successful submission:

- voucher becomes positively PRINTED;
- print operator is recorded;
- first print timestamp is correct;
- selection is cleared;
- opening the historical PDF does not itself create another physical-print
  audit;
- an intentional second print through "Stampa selezionati" is recorded as a
  reprint and becomes the latest print for security-threshold purposes.

A PDF render alone must never set PRINTED.

## 9. Gate H — use / expiry observation

For a disposable UAT voucher, authorize a guest through UniFi where practical
and synchronize Voucher Management.

Verify:

- first positive authorized-guest observation marks the voucher used;
- the cumulative count does not later fall locally if UniFi returns a lower
  value;
- first activation is not erased by a later null;
- a positive expired state does not regress;
- a used voucher never returns to a never-used/security-unused category.

Do not infer "last used" from synchronization timestamps.

## 10. Gate I — ordinary deletion

Use only a dedicated preparation-error UAT voucher that is:

- aligned;
- positively NOT_PRINTED;
- never physically printed;
- without positive use evidence.

Verify:

- fresh UniFi verification occurs;
- operator reason is mandatory;
- confirmation shows the reason;
- reason is durable locally;
- DELETE removes the voucher remotely;
- local history remains;
- deleted report shows date/source/reason.

Negative checks:

- PRINTED blocks ordinary deletion;
- UNKNOWN blocks ordinary deletion;
- positive use blocks ordinary deletion;
- missing alignment blocks ordinary deletion except the specifically supported
  blank-name external cleanup case.

## 11. Gate J — security review

Prefer an existing disposable/old UAT fixture or a copied test archive rather
than waiting for a new threshold to age.

Verify:

- printed-unused threshold is based on latest verified physical print;
- a reprint restarts the threshold;
- positive use removes the voucher from security-revocation candidacy;
- positively PRINTED legacy evidence with unknown print date is surfaced for
  immediate review;
- live UUID read occurs before destructive revocation;
- revocation removes only the intended UAT voucher from UniFi;
- code and local historical metadata remain readable in local audit/history.

## 12. Gate K — legacy import / reconciliation

Use a copy of the real legacy backup/history, never the only copy.

Verify:

- pre-SQLite ZIP import completes without treating arbitrary PDF numbers as
  voucher codes;
- PDF-generation-only evidence does not become physical print;
- legacy rows without expiry evidence are not fabricated as expired;
- verified legacy physical prints become positive print facts;
- after authoritative UniFi sync, the guided reconciliation is offered only
  when work remains;
- already-reconciled sessions do not repeatedly prompt;
- unresolved/ambiguous evidence is shown as such rather than guessed.

Critical convergence check when applicable:

- if an imported synthetic historical placeholder and a live UniFi UUID refer
  to the same voucher, verified legacy evidence ends on the live UUID;
- no duplicate synthetic/live business row remains after safe convergence;
- existing current prints are preserved and chronological first-print/reprint
  order is correct;
- ambiguous multiple live UUID matches stop automatic reconciliation.

## 13. Gate L — reports

From the Report workspace verify:

- guide opens and selects the intended report;
- Summary contains aggregates only;
- Used/Expired reports show useful lifecycle fields rather than UUID-heavy
  technical tables;
- Printed-unused shows print/use facts and live presence;
- Never-printed / threshold report shows creation age and nominality;
- Security Review uses latest print / immediate-review wording as appropriate;
- Deleted report shows reason prominently when one exists;
- externally detected deletion has no invented reason;
- Full Audit contains the technical identity/synchronization facts;
- "Ultima osservazione controller" corresponds to controller observation
  (last_seen_at);
- local synchronization is separately labeled;
- ordinary reports do not expose clear voucher codes;
- Full Audit exposes code only after explicit operator choice.

For PDF:

- generation opens preview first;
- Save Copy works;
- physical print from preview works;
- long notes do not make the PDF unprintable.

## 14. Gate M — backup / restart / restore

Verify a new protected backup:

- password protection is selected by default;
- backup completes and Home records it as successful;
- backup file is outside the managed application tree;
- application can close/reopen normally.

On a disposable UAT data root, restore the backup and verify:

- integrity validation succeeds;
- application restarts as required;
- live API root / Site association / TLS pin require the intended reconnection
  behavior;
- durable historical data remain available;
- no API key is restored;
- unresolved remote mutation state is not silently accepted.

## 15. Final acceptance record

Record only non-sensitive evidence:

- candidate commit SHA;
- GitHub Actions run ID;
- Windows version;
- display scaling(s) tested;
- UniFi Network version;
- Site fingerprint or non-sensitive Site label;
- printer path/model if relevant;
- pass/fail for Gates A–M;
- issue reference for every failure.

Never record:

- API key;
- voucher code;
- raw UUIDs when not needed;
- guest personal data in screenshots/transcripts.

## Release decision

5.1 can proceed to merge/tag/release only when:

- external code review has 0 open BLOCKER/HIGH;
- exact-candidate Windows CI is green;
- required Gates A–M applicable to the deployment are passed;
- any deviation is explicitly reviewed instead of silently waived.

A failed real-controller contract, identity, physical-print, destructive-workflow,
backup/restore or data-integrity check is a release stop.
